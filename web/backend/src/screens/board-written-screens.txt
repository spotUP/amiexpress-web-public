# Screens the BOARD writes for itself, as patterns.
#
# ONE COPY, TWO READERS. `screen-tables.ts` builds BOARD_WRITTEN_NAME from this
# file, and `docker-entrypoint.sh` greps it to decide which files the image must
# not copy over the board's own output. Neither owns it; neither mirrors it.
#
# It is a plain data file rather than a constant in either language because the
# two readers are TypeScript and POSIX sh, and every other way of sharing it
# ends in two copies and a test that tells you which one you already broke.
#
# It ships in the image: the Dockerfile carries `web/backend/src`, so the
# entrypoint can read it at /app/web/backend/src/screens/.
#
# ONE ENTRY PER LINE, a JavaScript regex source anchored whole by the reader.
# `#` starts a comment; blank lines are ignored.
#
# What earns an entry: something on this board WRITES the file. Not "the file is
# stale", not "nobody has drawn it" - a file nothing writes is an ordinary
# screen that happens to be old, and marking it here would hide it from the
# artists' gallery on the strength of a job that never runs.

# The callers log, written as callers come and go.
callerslog.*

# The last-caller screen, rewritten at every logon.
lastc\.txt

# The achievements leaderboard, rewritten every fifteen minutes. Its `.Header`
# and `.Tailer` are ART and are deliberately NOT here - a designer owns those.
achievetop\.txt

# QuickNew's new-files screen, regenerated by the door at every logoff. Tracked
# in git so a fresh board has something to show, which is exactly how the image
# came to overwrite the board's own output on every deploy (2026-09-15).
quicknew\.txt

# The requests bulletin, written by the REQUESTS door whenever a caller adds or
# changes a request. Here by NAME because its content is the sysop's own art
# with no marker in it - a door whose `Bulletin` setting names some other file
# loses the marking, the same caveat quicknew carries.
bull9\.txt

# Logs are never art.
.*\.log
